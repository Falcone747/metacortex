Methodology

How a metacortex is built.

A reference architecture for installing causal reasoning inside an enterprise. Built on Pearl's structural causal models, do-calculus, and Meadows' systems thinking.

1 · The three rungs of causation

Judea Pearl's Ladder of Causation distinguishes three levels of question a system can answer. Most enterprise analytics operates on the first; the metacortex operates on all three.

L1 — Association

P(Y | X) — what is observed? Given what I see in X, how does Y change? This is the regime of dashboards, regression, classical ML. Sufficient for prediction, insufficient for decision because confounders systematically distort the read.

L2 — Intervention

P(Y | do(X)) — what would happen if I acted? If I set X to a specific value, what does Y become? This requires severing the back-door paths that confounders open. A/B testing reaches L2; SCMs reach L2 systematically, including for never-tried values.

L3 — Counterfactual

P(Y_x | X', Y') — given what actually happened, what would have happened had X been different? The unique capability of structural causal models, computed via twin networks (Abduction-Action-Prediction). The basis of genuine organisational learning from past decisions.

The trap. Most enterprise "AI" today is L1 dressed as L2/L3. Predictions dressed as recommendations. Recommendations dressed as decisions. Every system that doesn't explicitly distinguish these three levels is conflating them — and the organisation learns to mistrust data.

2 · Building a structural causal model

An SCM for a sub-system (e.g. acquisition, operations, HR) is a tuple:

  • Variables U ∪ V — exogenous (U) and endogenous (V). The exogenous are uncaused within the model; the endogenous are determined by structural equations.
  • Structural equations — for each endogenous variable Vi: Vi = fi(Pa(Vi), Ui), where Pa are its parents in the DAG.
  • Acyclicity — the DAG is a DAG (no cycles). This is what makes the system computable.

Linear-Gaussian SCMs

For tractability, metacortex uses linear-Gaussian SCMs:

Vi = β₀ + Σⱼ βⱼ · Paⱼ + ε,   ε ~ N(0, σ)

This is enough to capture the structure of most business sub-systems. Closed-form formulas exist for intervention, and Monte-Carlo sampling makes counterfactuals cheap.

The diagnostic before the model

Before fitting equations, the metacortex performs a 3-step diagnostic of the actual organisation:

  1. Causal Loop Diagram (CLD) — actors, flows, feedback loops (R vs B), stocks, delays.
  2. Decision map (not the org chart) — who actually decides what, with what information, under what time constraint.
  3. Mental models — beliefs, dominant metaphors, contradictions across departments.

3 · Do-calculus — the engine of L2

Given an SCM, computing P(Y | do(X = x)) requires three operations from Pearl's do-calculus:

  1. Rule 1 (insertion/deletion of observations): rules for adding or removing variables from a conditioning set.
  2. Rule 2 (action/observation exchange): rules for when intervening and observing are equivalent.
  3. Rule 3 (insertion/deletion of actions): rules for when intervening can be removed from the formula.

Together, these rules let you mechanically compute the effect of an intervention without ever running the intervention itself.

Intervention = graph mutilation

In a linear-Gaussian SCM, intervening on X is equivalent to:

  1. Remove all incoming edges to X in the DAG.
  2. Set X = x.
  3. Re-evaluate downstream equations.

This is what the metacortex app does when you press "Run do(X)".

4 · Twin networks — the engine of L3

Counterfactuals use twin networks: two SCMs that share exogenous distributions but diverge in their interventions.

  1. Abduction — given the actual observed facts, infer the exogenous noise terms U for each variable.
  2. Action — in a twin SCM, override X with the counterfactual value x′.
  3. Prediction — using the SAME noise terms U from step 1, evaluate the twin SCM to get the counterfactual outcome Yx.

The result: a distribution of "what would have happened" conditioned on the actual world state. This is what enables genuine retrospective learning.

5 · Complex systems expertise

SCMs are necessary but not sufficient. Real businesses are complex systems with feedback loops, emergent behaviour, and tipping points. metacortex adds three complexity-aware layers:

Feedback loop detection

Every pair of mutually-causal variables in the DAG is annotated as R (reinforcing — growth or collapse) or B (balancing — equilibrium-seeking). Long-delay R-loops are flagged as "boom-bust risks".

Leverage points (Meadows)

Among all variables in the SCM, those with the highest total causal effect on the target outcome are surfaced as leverage points. The insight isn't always intuitive — sometimes a low-effort intervention on a "minor" variable dominates.

Bottleneck detection

Variables with high out-degree (many downstream effects) are flagged as bottlenecks. Single points of failure that the decision map doesn't make explicit.

6 · The Bayesian loop — L1 → L3 → update

A metacortex that doesn't learn is just an oracle. The architecture closes the loop:

  1. Every decision taken is logged with its predicted outcome (L2 distribution).
  2. Observed outcomes are matched against predictions (L3).
  3. Residuals feed back as SCM re-estimation via doubly-robust methods.
  4. Drift detection (KS test on residual distributions) flags when the world has changed and the SCM needs human review.

This is double-loop learning (Argyris): the system doesn't just correct errors, it corrects the premises that caused them.

What it isn't. The metacortex is not an oracle. It is a sparring partner for organisational reasoning. The human remains accountable. The system surfaces counterfactuals, the human decides.

7 · Reference stack

The reference implementation in this repository is intentionally minimal:

  • js/causal.js — SCM engine, do-calculus via graph mutilation, twin-network counterfactuals, leverage scoring, bottleneck detection, loop detection.
  • js/three-scene.js — 3D scene with Three.js (hero background + interactive DAG with orbit controls).
  • js/render.js — 2D DAG layout and SVG rendering (legacy, kept for fallback).
  • js/app.js — interactive app: SCM selection, counterfactual playground, insights.
  • data/examples.json — three reference SCMs (B2B SaaS acquisition, manufacturing delays, employee retention).

All MIT-style. Production-grade SCM engines can use DoWhy (Python), CausalNex, or EconML. The methodology is the asset; the stack is replaceable.
